买回摄像头接到 App#

网上买一台传统枪机，接到 RN 手机 App 看画面、登记设备。这是站长视角的逐步手册。先判断现场走 三条接入路径。运维细节（Compose、迅思维推流、边缘令牌）仍看 设备接入。界面规范看 三端 UI 与 UI/UX 系统 §9。

不是萤石 / 乐橙那种「扫二维码进厂商云」。不是 App Store。不是手机 24/7 拉流。只装 App 不承诺平台 24/7；见 接入路径。

先建立正确模型#

VistaCast 的手机 App 是 移动伴随：打开同一套 Admin，帮你登记和预览。真正拉枪机的是电脑 / 门店盒子上的 ai Worker。

网上买的传统枪机
        │  网线 + 电源（ONVIF / 局域网 RTSP）
        ▼
家里 / 店里的路由器
        │
        ├─ 电脑或门店盒子（Docker：server + Admin + ai）
        │         通电时持续拉流、心跳、检测（默认 stub；自运维，不是平台 24/7 SLA）
        │
        └─ 手机 RN App（Expo Go）
                  登录 → 接入向导 → 看门店画面
角色 做什么 不做什么
传统摄像头 在局域网打出 VLC 能播 的 RTSP 不装厂商 App 当唯一出流
电脑 / 门店盒子 跑 VistaCast；ai 持续拉流 不在 server/web 里加载模型
RN App 连局域网 Admin；向导里填 URL、测一帧、保存；再看列表 不替代盒子；底栏「检测」是本机摄像头 YOLO，不是枪机

三样东西必须在 同一局域网：枪机、跑栈的电脑、手机。

买什么、别买什么#

下单前问店家三句，答不上就换店：

  1. 是否 ONVIF Profile S，或至少能开局域网 RTSP？
  2. 主码流地址能否用 VLC 直接打开？
  3. 是否必须装萤石 / 乐橙 / 小米 App 才能出流？（必须 = 不要）
买 别买
海康 / 大华 / 宇视 工程枪机（写明 ONVIF） 萤石 / 乐橙 / 小米 / 涂鸦 只云回看
Reolink 有线、写明 ONVIF Ring / Nest / 只能厂商云的电池机
TP-Link VIGI（确认打开 ONVIF/RTSP） 「必须刷固件才出 RTSP」
1080p / 4MP；有 PoE 交换机就买 PoE 4K「AI 云端大模型」消费款

完整采购表：交付测试 C 节。

开箱：电源 + 网线 进路由器或交换机。给摄像头固定 IP（路由器 DHCP 预留最省事）。用说明书或 SADP / ConfigTool 找到 IP。

VLC 先过关：媒体 → 打开网络串流，粘贴下面模板（换成你的用户名、密码、IP）。没有画面，App 里也测不过。

品牌 实验室优先子码流
海康 rtsp://USER:PASS@IP:554/Streaming/Channels/102
大华 rtsp://USER:PASS@IP:554/cam/realmonitor?channel=1&subtype=1
宇视 rtsp://USER:PASS@IP:554/unicast/c1/s1/live
Reolink rtsp://USER:PASS@IP:554/h264Preview_01_sub

迅思维一类 推流机 不是默认可拉的工程 RTSP，走 设备接入 · 迅思维。

电脑侧先起栈#

手机填的是 电脑的局域网地址，不是摄像头 IP。栈没起来，App 连不上。

cd deploy
cp .env.example .env
docker compose up --build

Admin：http://电脑LAN_IP:13101 （例如 http://192.168.31.20:13101）。本机浏览器先能打开，再去手机。门店盒子一键包见 门店盒子。

查电脑 IP：macOS ifconfig，Windows ipconfig。

RN App 从哪进#

pnpm --dir mobile start

用 Expo Go SDK 57 扫码。真机不要填 127.0.0.1（那是手机自己）。

屏 1 · 连局域网控制台#

未登录不出现底栏。先填 Admin 地址，点连通。

┌─────────────────────────────┐
│  VistaCast                  │
│  连接局域网控制台             │
│                             │
│  Admin 地址                 │
│  ┌───────────────────────┐  │
│  │ http://192.168.31.20  │  │  ← 电脑 LAN IP
│  │ :13101                │  │
│  └───────────────────────┘  │
│                             │
│  [ 测试连通 ]                │
│                             │
│  ⚠ 127.0.0.1 是本机，        │
│    不是电脑                  │
└─────────────────────────────┘

通了之后打开 同一套 Admin 登录页（不是第二套密码）。

屏 2 · 登录后首页#

底栏：首页 / 检测 / 控制台 / 设置。首页三条路：

┌─────────────────────────────┐
│  首页                       │
│                             │
│  ┌───────────────────────┐  │
│  │  移动巡检              │  │  → 底栏「检测」
│  │  本机摄像头 YOLO       │  │     不是枪机
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │  看门店画面            │  │  → /#/cameras
│  │  已接入的枪机列表      │  │
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │  接入摄像头            │  │  → /#/setup?device=mobile
│  │  买回来的枪机走这里    │  │
│  └───────────────────────┘  │
│                             │
│  首页   检测   控制台   设置 │
└─────────────────────────────┘
你要点 打开 用来干什么
接入摄像头 /#/setup?device=mobile 登记新枪机（本手册主路径）
看门店画面 /#/cameras 已保存的枪机；点行进预览
底栏 检测 client-infer?surface=mobile 手机前置/后置摄像头演示，不是刚买的枪机
底栏 控制台 先主机向导，再 WebView 默认可达后也是摄像头列表；顶上可切到接入向导

RN 不另做一套摄像头表单。点「接入摄像头」之后，你看到的就是手机宽度下的 Admin 设备接入中心。

接入向导点哪里#

深链打开 设备接入，默认选中「摄像头」。三步：站点 → 拉流地址 → 测试并保存。

┌─────────────────────────────┐
│  设备接入                    │
│  摄像头  |  边缘盒  |  手机  │  ← 买回来的枪机选「摄像头」
│                             │
│  1. 站点                    │
│     [ 选择已有站点        ▾] │
│                             │
│  2. 拉流                    │
│     协议  [ RTSP          ▾] │
│     地址                    │
│     ┌─────────────────────┐ │
│     │ rtsp://user:pass@   │ │
│     │ 192.168.31.55:554/… │ │  ← 与 VLC 同一条
│     └─────────────────────┘ │
│     [ 局域网发现 ]  可选     │  ← ONVIF 只列设备，
│                             │     不会自动填码流
│  3. 探测                    │
│     [ 测试拉流 ]             │
│                             │
│     ○ 通过  1920×1080  1.2s │
│       或                    │
│     ○ 失败  对照下方诊断     │
│                             │
│     [ 保存 ]                 │  ← 探测通过才启用
└─────────────────────────────┘

操作顺序：

  1. 设备类型保持 摄像头（不要选边缘盒 / 手机伴随）。
  2. 选站点。没有站点就先在 Admin 建一个。
  3. 协议 RTSP。把 VLC 能播的地址完整粘进去（含用户名密码）。
  4. 可选：点发现，从列表认出这台机，仍然要手填 VLC 那条 URL。发现 不是 ONVIF GetStreamUri。
  5. 点 测试拉流。成功只说明此刻能解出一帧，不写在线状态、不改心跳。
  6. 通过后再 保存。列表出现新行和 UUID。

密码会出现在 URL 里。列表和探测结果会脱敏 user:pass@。不要把带密码的地址贴进可截图的群。

探测失败时向导用 ErrorState + 诊断文案，不甩 ffmpeg 原文。对照：

向导提示 你改什么
目标被禁止 不要填 127.0.0.1 / localhost。填摄像头的 192.168.x
DNS 失败 主机名不对；Docker 名 mediamtx 只在 Compose 网内有效
连接被拒绝 / 超时 IP、端口、网段、防火墙；枪机和盒子要能互相访问
认证失败 用户名密码；有的机型要「ONVIF 用户」而不是网页管理员
RTSP 握手失败 路径不对。换主码流 / 子码流，再回 VLC 试
编码不支持 / 无视频轨 改 H.264 子码流；不要只开音频
超时无帧 先降分辨率。迅思维直拉 :554 会走这里，改推 MediaMTX

改完 URL 再点一次 测试拉流。改 URL 不会自动把旧心跳改掉。

保存之后：看画面 vs 持续在线#

你想确认的 在 App 里怎么走 实际含义
登记成功 首页 看门店画面，列表有新行 控制面已有这条摄像头
此刻有图 点该行 预览 JPEG 预览；不是厂商云回看
状态 online 列表 Last heartbeat 在更新 本机 ai 在持续拉流。探测成功 不等于 在线

单节点 Compose 的 ai 一次只拉一路。要 24/7 心跳，把保存后的 UUID 和同一条地址写入电脑 deploy/.env，再重启 ai：

CAMERA_ID=<保存后的摄像头 UUID>
SOURCE_URL=rtsp://USER:PASS@192.168.x.x:554/Streaming/Channels/102
SOURCE_KIND=rtsp
docker compose up -d ai

步骤与实验室口径见 用户买回摄像头。检测默认仍是 stub，不是生产 F1。

预览走 Admin 深色视频区。底栏「检测」对准人脸出框，那是窗口 WASM，不要当成枪机已接入。

浏览器也能做同一套向导#

电脑浏览器打开 http://localhost:13101/#/setup（或 LAN IP）。Electron 首页「接入摄像头」打开 /#/setup?device=edge。三端共用一张表单，避免填两次。

Web 侧栏：总览 → 设备接入。窄屏侧栏收成抽屉，手机 WebView 同样走这套步进。

做完自检#

  • 枪机、电脑、手机同一局域网；枪机有固定 IP
  • VLC 能播子码流
  • 电脑 Admin :13101 能打开
  • RN 填电脑 LAN IP，登录后首页能看到「接入摄像头」
  • 向导 测试拉流 通过后再保存
  • 「看门店画面」能点进预览
  • 需要 online 时已绑定 CAMERA_ID / SOURCE_URL 并重启 ai

现场勾选：交付测试 C / E2 / H。排障扩表：设备接入 · 诊断。多协议（RTMP / HLS / 国标）：进流。
